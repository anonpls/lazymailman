# Lazy Mailman

Lazy Mailman — небольшой Python-инструмент для рассылки текстовых писем по списку получателей. Проект умеет отправлять письма через SMTP, читать настройки из `.env` без внешних зависимостей и запускать тестовую рассылку в Telegram вместо реальной отправки email.

## Возможности

- чтение списка получателей из TXT-файла;
- настройка отправителя, темы, файла текста письма и окна активности рассылки через переменные окружения или `.env`;
- отправка писем через SMTP, по умолчанию через Gmail SMTP;
- настраиваемая пауза между реальными email-отправками;
- ограничение реальной email-рассылки системным временем активности;
- логирование успешных и неуспешных SMTP-отправок в файл;
- fallback-отправитель для повторной попытки, если отправка с основного адреса не удалась;
- тестовый режим с отправкой превью сообщений в Telegram;
- переформулировка текста письма через OpenRouter API для каждого получателя по флагу `--rewriter`.

## Требования

- Python 3.10 или новее;
- SMTP-аккаунт для отправки писем;
- для Gmail — app password, а не обычный пароль от аккаунта;
- Telegram Bot Token и Chat ID, если нужен тестовый режим;
- OpenRouter API key, если используется `rewriter.py`.

Проект использует только стандартную библиотеку Python, поэтому устанавливать зависимости через `pip` не нужно.

## Быстрый старт

1. Склонируйте репозиторий и перейдите в директорию проекта.
2. Создайте файл `.env` в корне проекта.
3. Заполните список получателей в `emails.txt` — по одному email на строку.
4. Запустите тестовую рассылку в Telegram или реальную отправку email.

## Настройка `.env`

Минимальный пример для отправки email через Gmail:

```env
EMAIL_SENDER=sender@example.com
GMAIL_APP_PASSWORD=your-gmail-app-password
EMAIL_SUBJECT=Коммерческое предложение
EMAIL_BODY_FILE=email.txt
MAILING_ACTIVE_FROM=08:00
MAILING_ACTIVE_TO=23:00
```

Пример с дополнительными настройками:

```env
EMAIL_SENDER=sender@example.com
GMAIL_APP_PASSWORD=your-gmail-app-password
SMTP_SERVER=smtp.gmail.com
SMTP_PORT=587
EMAILS_FILE=emails.txt
EMAIL_SUBJECT=Коммерческое предложение
EMAIL_BODY_FILE=email.txt
MAILING_ACTIVE_FROM=08:00
MAILING_ACTIVE_TO=23:00

TELEGRAM_BOT_TOKEN=123456:telegram-bot-token
TELEGRAM_CHAT_ID=123456789
TELEGRAM_TEST_DELAY_SECONDS=1

OPENROUTER_API_KEY=sk-or-your-openrouter-key

EMAIL_SEND_DELAY_SECONDS=2
EMAIL_SEND_LOG_FILE=mailing.log
FALLBACK_EMAIL_SENDER=fallback@example.com
FALLBACK_GMAIL_APP_PASSWORD=your-fallback-gmail-app-password
```

### Переменные окружения

| Переменная | Обязательна | Значение по умолчанию | Описание |
| --- | --- | --- | --- |
| `EMAIL_SENDER` | Да | — | Email отправителя. Вместо нее также можно задать `GMAIL_EMAIL`. |
| `GMAIL_APP_PASSWORD` | Да для email-рассылки | — | Пароль приложения для SMTP-авторизации. |
| `SMTP_SERVER` | Нет | `smtp.gmail.com` | SMTP-сервер. |
| `SMTP_PORT` | Нет | `587` | SMTP-порт. |
| `EMAILS_FILE` | Нет | `emails.txt` | Путь к файлу со списком получателей. |
| `EMAIL_SUBJECT` | Нет | `Коммерческое предложение` | Тема письма. |
| `EMAIL_BODY_FILE` | Нет | — | Путь к текстовому файлу с телом письма. Если задан, имеет приоритет над `EMAIL_TEXT`. |
| `EMAIL_TEXT` | Да, если не задан `EMAIL_BODY_FILE` | пустая строка | Текст письма из `.env`. Оставлен как fallback; для реального письма лучше использовать `EMAIL_BODY_FILE`. |
| `MAILING_ACTIVE_FROM` | Нет | — | Начало периода реальной рассылки по системному времени в формате `HH:MM`, например `08:00`. |
| `MAILING_ACTIVE_TO` | Нет | — | Конец периода реальной рассылки по системному времени в формате `HH:MM`, например `23:00`. |
| `EMAIL_SEND_DELAY_SECONDS` | Нет | `0` | Пауза между реальными email-отправками в секундах. |
| `EMAIL_SEND_LOG_FILE` | Нет | `mailing.log` | Файл для логирования результата каждой SMTP-отправки. |
| `FALLBACK_EMAIL_SENDER` | Нет | — | Запасной email-отправитель для повторной попытки, если основной SMTP-send завершился ошибкой. |
| `FALLBACK_GMAIL_APP_PASSWORD` | Нет | `GMAIL_APP_PASSWORD` | Пароль приложения для запасного отправителя. Если не задан, используется основной пароль. |
| `TELEGRAM_BOT_TOKEN` | Да для тестового режима | — | Токен Telegram-бота. |
| `TELEGRAM_CHAT_ID` | Да для тестового режима | — | ID чата, куда отправлять тестовые сообщения. |
| `TELEGRAM_TEST_DELAY_SECONDS` | Нет | `0` | Пауза между тестовыми сообщениями в секундах. |
| `OPENROUTER_API_KEY` | Да для `rewriter.py` | — | Ключ OpenRouter API. |

## Файл с текстом письма

Рекомендуемый способ задать тело письма — положить текст в отдельный файл и указать путь через `EMAIL_BODY_FILE`.

```env
EMAIL_BODY_FILE=email.txt
```

Пример `email.txt`:

```txt
Здравствуйте!

Хотим предложить вам сотрудничество.
```

Если `EMAIL_BODY_FILE` не задан, проект использует старую переменную `EMAIL_TEXT` из `.env`.

## Файл получателей

По умолчанию получатели читаются из `emails.txt`. Формат простой: один email на строку.

```txt
client1@example.com
client2@example.com
client3@example.com
```

Пустые строки игнорируются.

## Использование

### Реальная email-рассылка

```bash
python main.py
```

С другим файлом получателей:

```bash
python main.py --emails-file path/to/emails.txt
```

С переформулировкой письма перед каждой отправкой:

```bash
python main.py --rewriter
```

С паузой между реальными отправками и отдельным файлом лога:

```bash
python main.py --send-delay 2 --log-file logs/mailing.log
```

С fallback-отправителем для повторной попытки при SMTP-ошибке основного адреса:

```bash
python main.py --fallback-sender fallback@example.com
```

При включенном `--rewriter` текст письма перед отправкой каждому получателю отдельно отправляется в OpenRouter, поэтому каждая итерация рассылки получает новый вариант формулировок.

### Тестовая рассылка в Telegram

Тестовый режим не отправляет email. Вместо этого для каждого получателя он отправляет в Telegram сообщение с отправителем, получателем, темой и текстом письма.

```bash
python main.py --test
```

Тестовая рассылка также поддерживает переформулировку для проверки итоговых вариантов без отправки email:

```bash
python main.py --test --rewriter
```

Также можно запустить тестовый скрипт напрямую:

```bash
python tests/tg-test.py
```

Или указать другой файл получателей:

```bash
python tests/tg-test.py --emails-file path/to/emails.txt
```

Для прямого запуска тестового скрипта с переформулировкой:

```bash
python tests/tg-test.py --rewriter
```

## Переформулировка письма через OpenRouter

В `rewriter.py` есть функция `rewrite_email(template_text, iteration=None)`, которая отправляет текст письма в OpenRouter и возвращает переформулированную версию с сохранением смысла, стиля, цели, фактов, ссылок и контактов. CLI использует ее по флагу `--rewriter` отдельно для каждого получателя.

Пример использования из Python:

```python
from rewriter import rewrite_email

new_text = rewrite_email("Здравствуйте! Это исходный текст письма.")
print(new_text)
```

Для работы нужен `OPENROUTER_API_KEY` в `.env` или переменных окружения.

## Логирование, fallback и проверка спама

Каждая реальная SMTP-отправка пишет в `EMAIL_SEND_LOG_FILE` строку со статусом `success` или `failure`, адресом отправителя, получателем, типом попытки (`primary` или `fallback`) и ошибкой SMTP/авторизации, если она была.

Fallback-отправитель используется только когда основной SMTP-вызов завершился ошибкой или SMTP явно отклонил получателя. Если основной SMTP-сервер принял письмо к доставке, стандартный SMTP уже не сообщает отправителю, попадет письмо во входящие, промо, спам или будет отфильтровано на стороне получателя. Поэтому автоматическую проверку попадания в спам для произвольных получателей сделать надежно нельзя без доступа к почтовому ящику получателя или внешнего deliverability-сервиса. В логе это отражается как `spam_check=not_supported_by_smtp`.

## Безопасность

- Не коммитьте `.env`, пароли приложений, Telegram-токены и API-ключи.
- Для Gmail используйте пароль приложения.
- Перед реальной рассылкой сначала запускайте `python main.py --test`, чтобы проверить текст и список получателей.
- Убедитесь, что у вас есть законное основание отправлять письма указанным получателям.

## Проверка конфигурации

Если какая-то обязательная переменная не задана, скрипт завершится с ошибкой и сообщит, чего не хватает: отправителя, пароля SMTP, текста письма или Telegram-настроек.
